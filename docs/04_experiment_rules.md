# 04. 실험 규칙 (개별 모델링 방식)

개편일: 2026-10-31. 기존의 "피처는 수아, 튜닝은 한동" 식 역할 분담을 없애고, **세 명 모두 각자 RMSE를 낮추는 모델링을 하는 방식**으로 바꾼다. 한 명이 실험하는 동안 다른 사람이 기다리는 일을 없애는 게 목적이다.

## 1. 방식 요약
1. 각자 자기 아이디어(피처·모델·튜닝·앙상블 무엇이든)로 **같은 잣대**에서 RMSE를 낮춰 본다.
2. **RMSE가 낮아지면 채택 → 낮아진 이유를 팀에 전달한다.**
3. **변화가 없거나 나빠지면 버린다 → 그 이유도 팀에 전달한다.** 버린 실험도 기록해 둬야 다른 사람이 같은 걸 다시 하지 않고, 이 기록이 방법론 문서의 재료가 된다.
4. 11/3에 각자 채택분을 합쳐 최종 조합을 정한다.

## 2. 역할
| 구분 | 담당 |
|---|---|
| 모델링·실험 | **수아·재혁·한동 전원**. 아이디어 종류는 제한 없음 |
| 공통 파일 관리 | 재혁: `00_baseline.ipynb`, `outputs/common/`(fold·홀드아웃), `requirements.txt` |
| 통합·최종 | 재혁: 11/3 채택분 통합, 11/4 재현 실행, 제출 코드 정리 |
| 방법론 문서 | 전원이 자기 실험 기록을 제공, 재혁이 취합 |

## 3. 공통 잣대 (모두 같아야 비교가 된다)
| 항목 | 값 |
|---|---|
| 데이터 | train의 dev 사상 104개 (홀드아웃 18개 제외) |
| fold | `outputs/common/event_folds.csv` (사상 단위 4-fold). **직접 만들지 않는다** |
| 지표 | dev OOF RMSE, fold별 RMSE, 사상별 RMSE |
| 공통 기준(baseline) | **0.2178** (fold 0.2479 / 0.2255 / 0.1857 / 0.2073, 피처 72개, LightGBM 고정 파라미터 + `deterministic=True, force_row_wise=True, num_threads=4`, seed 42). 10/31 hou 환경에서 `00_baseline`으로 확정 |
| 환경 | conda 환경 `hou`: Python 3.13 / numpy 2.3.5 / pandas 2.3.3 / scikit-learn 1.7.2 / lightgbm 4.7.0 (`requirements.txt`). **실험 전 각자 hou 환경에서 기준을 다시 돌려 0.2178·fold 값이 같은지 확인**하고, 다르면 자기 기준값 대비로 판정 |
| seed | 기준 비교는 42 |

**환경 통일**: 같은 코드·fold인데 실행 환경(라이브러리 버전)만 달라도 전체 RMSE가 0.0004, fold 하나는 최대 0.002 달라진 적이 있다 (10/30 최초 실행 0.2182 → 10/31 재실행 0.2178). 채택 기준(0.0005)과 비슷한 크기라서 아래를 지킨다.
- 기준값은 다른 사람 PC나 옛 결과에서 **옮겨 적지 않는다.** 실험할 때마다 같은 환경에서 기준을 함께 돌려 그 값과 비교한다.
- 팀 공통 라이브러리 버전은 `requirements.txt`로 정하고 재혁이 확정한다 (현재 파일은 pandas 3.0.2·sklearn 1.8.0인데 실제 돌린 환경은 pandas 2.3.3·sklearn 1.7.2).

모델이나 파라미터를 바꾸는 실험에서도 fold와 지표는 그대로 쓴다. 다른 fold·다른 지표로 낸 숫자는 비교에 쓰지 않는다.

## 4. 실험 한 건의 절차
1. **공지**: 시작 전에 팀 채팅에 한 줄 ("수아: 유역×강우 피처 해봄"). 같은 걸 둘이 하는 걸 막는다.
2. **가설**: 왜 RMSE가 줄 것 같은지 한 문장. (예: "큰 유역은 반응이 느려 24h 강우가 중요할 것")
3. **구현**: 자기 노트북에서. 공통 파일은 수정하지 않는다.
4. **누수 자가검증**: 피처를 건드렸으면 필수 (사상 마지막 6시간 삭제 후 재계산 → 값 동일). 통과 못 하면 학습하지 않는다.
5. **CV 실행**: 공통 fold로 dev OOF RMSE, fold별 RMSE 계산.
6. **판정**: 아래 5번 기준.
7. **원인 확인**: 사상별·구간별로 어디가 달라졌는지 본다 (아래 6번).
8. **기록과 공유**: experiments.csv에 한 줄, 팀 채팅에 요약.

## 5. 채택·기각 기준
- **채택**: 비교 대상 대비 dev OOF RMSE가 **0.0005 이상 감소**하고, 4개 fold 중 **3개 이상**에서 개선.
- 그 외는 **기각**. 단 개선 폭이 0.0005~0.001이면 seed를 바꿔 한 번 더 돌려 같은 방향인지 확인하길 권장 (우리 1차 실험 변동이 ±0.0005 수준이었음).
- **비교 대상**: 처음에는 공통 기준(0.2178). 자기 채택분 위에 계속 쌓을 때는 **직전 채택본** 대비로 판정하고, 공통 기준 대비 누적 변화도 같이 적는다.
- 피처끼리 정보가 겹치므로 "이 변수가 독립적으로 얼마 기여했다"고 단정하지 않는다. "기준 위에 이 묶음을 더했을 때의 효과"로 적는다.
- 목적함수는 MSE (평가가 RMSE).

## 6. 기록과 설명
### 6-1. 파일: `outputs/<이름>/experiments.csv` (커밋함)
| 컬럼 | 내용 |
|---|---|
| exp_id | `suah_01` 식 번호 |
| idea | 한 줄 이름 |
| hypothesis | 가설 |
| change | 바뀐 것 (피처 목록 또는 파라미터) |
| n_features | 피처 수 |
| oof_rmse | dev OOF RMSE |
| delta_vs_ref | 비교 대상 대비 변화 (음수=개선) |
| delta_vs_base | 공통 기준 대비 누적 변화 |
| fold_rmse | 4개 fold 값 |
| folds_improved | 개선 fold 수 |
| verdict | 채택 / 기각 / 보류 |
| reason | 이유 두 줄 이내 |
| code | 노트북 이름과 셀·함수 위치 |

OOF 값 전체(`oof_*.csv`)는 용량이 커서 드라이브에 올리고 git에는 올리지 않는다 (`.gitignore` 반영됨).

### 6-2. 설명: "왜 좋아졌나 / 왜 안 좋아졌나"
숫자만 올리지 않고, 아래 중 해당하는 것을 확인해서 이유에 쓴다.
- 정답이 큰 구간(예: > 0.5 m)과 나머지 구간의 RMSE가 각각 어떻게 변했나
- 오차 상위 10개 사상이 좋아졌나, 나머지 사상이 나빠졌나
- 가설이 맞았나. 안 맞았으면 이미 기존 피처가 같은 정보를 갖고 있었던 건 아닌지
- (모델 변경이면) 과적합·과소적합 중 어느 쪽이었나, 반복 수는 어땠나

### 6-3. 팀 채팅 양식
```
[이름] 실험 이름
기준 0.2178 -> 0.21xx (Δ -0.00xx) | 개선 fold n/4 | 채택 / 기각
이유: (가설이 맞았나, 어디가 달라졌나)
다음: (이어서 할 것)
```
하루 한 번 이상 올린다.

## 7. 통합과 홀드아웃 (11/3)
- 각자 채택분의 **피처 생성 코드·파라미터·비교 결과**를 재혁에게 넘긴다. 목록(json)만으로는 재현이 안 된다.
- 재혁이 채택 묶음을 **개선 폭이 큰 순서로 하나씩** 얹어 합치고, 얹을 때마다 같은 기준으로 재검증한다. 합쳐서 나빠지면 충돌하는 묶음을 찾아 뺀다.
- 서로 다른 모델을 앙상블할 때는 각자 OOF를 같은 fold 기준으로 맞춰 평균해 본다.
- **홀드아웃은 개인이 열지 않는다.** dev OOF로 팀 최종 조합 1개를 정한 뒤, 재혁이 그 1개에 대해서만 한 번 확인한다. 결과로 조합을 다시 고르지 않는다 (여러 번 보면 낙관적으로 변함).
- 미정: 최종 제출 모델을 122개 사상 전체로 다시 학습할지. 학습한다면 반복 수는 CV best_iteration 평균으로 통일.

## 8. 지켜야 하는 것 (변경 없음)
- 행 t 예측에는 시점 t 이하 정보만. 같은 관측소 t+1~t+6 행 참조 금지
- 허용: 같은 관측소 이전 행, 같은 사상 다른 관측소의 시점 t·t 이전 값 (Q&A 10/6)
- 금지: 사상 종료시점·전체 길이 등 미래 행 의존 정보, 외부 원자료 대조
- 관측소 통계·관계는 train(dev)으로만
- fold는 공통 파일, 행 단위 무작위 분할 금지
- git: 자기 브랜치·자기 노트북만, 공통 파일은 재혁만, PR 후 재혁 머지. 커밋·push는 본인이 직접

## 9. 실험 아이디어 풀 (누구나 골라서 한다, 공지 먼저)
| 갈래 | 아이디어 | 비고 |
|---|---|---|

| 피처 | 감조 관측소 플래그 | 팀 기존 목록 필요. 수위 패턴만으로 판단 금지 |

| 앙상블 | seed 평균, 모델 간 평균 | |
| 구조 | 미래 강우 보조모델, 이웃 관측소 lag | 규정상 허용이지만 일정상 보류 |
