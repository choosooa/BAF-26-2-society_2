# KISTI 수위예측 모델링 — EDA 검토와 전략 세분화 계획

> 작성 2026-10-31 · 한동(모델 비교·튜닝 담당)

## 0. 요약

1. EDA 자체는 지침을 잘 따랐다. 특히 반박(S7)과 군집 검증(S5)은 지침 이상이다. 약한 곳은 처리 민감도(S2), 시각화 모수 기록(S3·S4), "미확인" 층과 후속 질문(S8)이다.
2. 더 큰 구멍은 **EDA에서 모델링으로 넘기는 과정**이다. EDA 결정 목록의 피처 1·4·5·8순위가 파이프라인에 없다. EDA가 권한 평가지표 3종 중 2개도 쓰지 않고 있다.
3. OOF 진단 결과, 예측은 **이미 보정되어 있다**(예측 0.5 초과 구간에서 E[y|ŷ]의 기울기 1.02). 큰 상승을 낮게 예측하는 −0.44m 편향은 보정 문제가 아니라 **구별력 문제**다. 그래서 손실 함수를 바꾸거나 후처리를 하거나 튜닝을 더 해도 이 편향은 거의 줄지 않는다. 줄이려면 **새 정보**를 넣어야 한다.
4. 지금까지 튜닝으로 얻은 개선(−0.0022)은 실재하지만 작다. 사상 부트스트랩 95% 구간이 [−0.0041, +0.0000]이다. 큰 상승 편향은 −0.436에서 −0.448로 그대로다.
5. 11/3 조합 확정까지 실험할 수 있는 날은 사흘이다. 권장안은 **B(균형형)**다. 평가 틀을 보강하고, 조석 전문가 모델을 시험하고, 수아의 EDA 근거 피처(상류 관측소, q × 강우)를 받아 적용한다.

## 2. 진단 — 지금 오차는 어떤 종류인가

### 2.1 구간별 오차 (LightGBM 기준 모델, dev OOF 0.2178)

| 구간 | 행 비중 | 오차제곱합 비중 | RMSE |
|---|---|---|---|
| 일반 | 62.2% | 60.7% | 0.215 |
| 초단기 의심(108곳) | 23.3% | 19.5% | 0.199 |
| **조석 15곳** | **3.2%** | **9.8%** | **0.380** |
| 댐 방류 의심 23곳 | 5.1% | 6.9% | 0.253 |
| 보 관리수위 의심 | 4.4% | 2.2% | 0.154 |
| 약한 조석·24h 주기·고정 | 1.8% | 1.0% | – |

- 비조석 RMSE는 0.2105다.
- 상위 5개 사상이 오차제곱합의 58.2%를 차지한다. 상위 5사상을 빼면 RMSE는 0.1595이고, 튜닝 후 0.1560이다.
- 조석 구간은 행 비중의 3배에 해당하는 오차를 낸다. EDA는 HGB 기준으로 조석 오차 몫을 8.8%라 보고 후순위로 미뤘다. LightGBM에서도 9.8%라 판단은 같지만, 조석 15곳만 따로 학습하는 실험은 비용이 작아 시험해 볼 가치가 있다.

### 2.2 보정 상태 — 핵심 진단

예측값을 20분위로 나눠 칸마다 실제 평균을 비교했다.

| 예측 구간 | 예측 평균 | 실제 평균 |
|---|---|---|
| 상위 5% | 1.129 | 1.106 |
| 상위 1% | 2.652 | 2.684 |
| 상위 0.1% | 5.632 | 5.718 |

예측이 0.5를 넘는 행만 보면 실제값을 예측값에 회귀한 기울기는 1.02다. 즉 E[y | ŷ] ≈ ŷ이다.

**해석(도출)**: MSE를 최소화하는 예측은 조건부 평균 E[y|x]다. 이 예측이 잘 보정되어 있어도, 정답 y가 큰 행만 골라 보면 예측은 0 쪽으로 줄어 있다. 조건을 ŷ이 아니라 y에 걸었기 때문에 생기는 평균으로의 회귀다. 따라서 docs/02에 적힌 "정답 0.5m 초과 구간 평균 −0.24 ~ −0.84"는 모델이 고칠 수 있는 편향이 아니다. 예측을 키우는 후처리(스트레칭, 분위수 보정)를 하면 같은 예측값을 받는 정체 행의 오차가 커진다.

**결론**: RMSE를 움직이는 길은 Var(E[y|x])를 키우는 것, 곧 **x에 정보를 더해 "곧 오를 행"과 "계속 정체할 행"을 갈라 주는 것**뿐이다. 하이퍼파라미터·손실·후처리는 이 길이 아니다.

- 반증 조건: early stopping을 검증 fold로 했기 때문에 OOF가 약간 낙관적이다. 고정 반복 수로 다시 계산했을 때 상위 구간 기울기가 1보다 뚜렷하게 크게 나오면(예: 1.1 이상) 후처리 보정을 다시 검토한다.

### 2.3 튜닝 개선의 신뢰도

기준과 최종(블렌딩)의 사상별 오차제곱합 차이를 104개 사상 단위로 5,000회 부트스트랩했다.

- ΔRMSE 평균 −0.0022, 95% 구간 [−0.0041, +0.0000], 개선 확률 97%
- 사상의 87%에서 개선됐다
- fold 기준(3/4)보다 사상 단위 판정이 더 많은 정보를 준다. 새 fold를 만들지 않아도 되므로 팀 규칙(fold는 재혁 매핑만 사용)과도 충돌하지 않는다

| M8 | 잔여 튜닝: `learning_rate` 0.02 + 반복 증가, `feature_fraction` 0.4~0.5 | 소폭 개선 | 낮음 | 작음 | 피처가 바뀐 뒤 한 번만 한다 |

**하지 않는 것**: Huber·분위수 손실(RMSE 기준에서는 꼬리를 덜 맞춘다), 타깃 로그 변환(평균이 어긋난다), 예측 스트레칭 후처리(2.2절), 신경망(시간 부족, EDA 근거 없음).

## 4. 선택지 — 남은 사흘

| 안 | 구성 | 기대 | 위험 |
|---|---|---|---|
| A 안정형 | E1~E4 + M5·M6·M8 + 블렌딩 재산정 | −0.001 ~ −0.003 | 낮음. 큰 상승 편향은 그대로 남는다 |

### 코드 뼈대

q는 fit(학습 fold) / transform 형태로 넘겨주면 한동 쪽에서 fold마다 호출할 수 있다.

```python
def fit_wl_ref(dev):
    # 관측소별 학습 fold wl_t 정렬 배열
    return {s: np.sort(v.values) for s, v in dev.groupby("station_id")["wl_t"]}

def wl_quantile(df, ref):
    q = np.full(len(df), np.nan)
    for s, idx in df.groupby("station_id").indices.items():
        if s in ref:
            q[idx] = np.searchsorted(ref[s], df["wl_t"].values[idx], side="right") / len(ref[s])
    return q
```

도착 예정 비는 베이스라인 `lag()`(정확히 k시간 전 행만 사용)로 `sfc_rain_1h_lag1~5`를 만든 뒤 합한다.

```python
L = pd.read_csv("eda/cache/results/nb09_station_lag.csv").set_index("station_id")["L"]

def arriving_rain(df, L):
    l = df["station_id"].map(L).fillna(L.median()).round().astype(int).values
    out = np.zeros(len(df))
    for k in range(6):
        col = df["sfc_rain_1h"] if k == 0 else df[f"sfc_rain_1h_lag{k}"]
        use = (k >= l - 6) & (k <= l - 1)
        out += np.where(use, col.fillna(0).values, 0.0)
    return out
```
